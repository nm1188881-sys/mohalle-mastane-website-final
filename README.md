# Mohalle Mastane Trust

Community animal welfare website for Rourkela: rescue awareness, community participation, fundraising, events and the Trust’s vision.

## Local development

Use Node.js 22.12 or later and npm.

```sh
npm ci
npm run dev
```

For optional local Supabase testing, copy `.env.example` to `.env.local` and supply the public project URL and publishable/anon key. Never commit secrets.

```sh
npm run typecheck
npm run build
```

## Project structure

| Path | Purpose |
| --- | --- |
| `src/routes/` | Homepage, community, vision, fundraising and events pages |
| `src/components/` | Shared website components |
| `src/components/ui/` | Reusable interface primitives |
| `src/config/site.ts` | Public contact details and external links |
| `src/data/` | Story content |
| `src/assets/` | Images and source asset metadata |
| `src/hooks/` | Shared React hooks |
| `src/lib/` | Utilities and optional database integration |
| `public/` | Files served directly |
| `supabase/migrations/` | Versioned database schema |
| `supabase/functions/` | Optional volunteer notification function |
| `docs/` | Setup, handover and change history |

`src/routeTree.gen.ts` is generated by the router; edit route files instead.

## Current behavior

- Public volunteer registration uses Google Forms. The Supabase test form is development-only.
- Donation buttons open the Trust’s Razorpay payment page. The website does not verify or record completed payments.
- Supabase migrations and notification code are included for future activation; they are not deployed by copying these files.

## Launch blockers

Several image metadata files refer to Lovable-only asset URLs. The actual logo and photographs must be recovered and installed before launch. Contact details, event content and fundraising claims also need the Trust’s review. A build alone does not verify deployed behavior.

Read [setup](docs/SETUP.md), [handover](docs/HANDOVER.md) and [change history](docs/CHANGES.md).

## Repository workflow

This repository is linked to Lovable. Preserve published history and use a feature branch and pull request for review. Keep application source at the repository root rather than uploading the ZIP as a single file. Use `package-lock.json` with `npm ci` for reproducible installs; the existing Bun files remain for compatibility.
